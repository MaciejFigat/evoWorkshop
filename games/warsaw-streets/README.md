# WARSAW STREETS

Original early-90s style side-scrolling beat 'em up. HTML5 Canvas + plain JavaScript, no frameworks, no build step.

**Current state: Stages 2 + 3 of the plan.** Playable: Nina vs. Mafia Goons on Stage 1 (Vistula boulevard, 3 enemy waves, stage clear, lives, game over). Ray, Mitsuyo, the other three enemies, stages 2-6, menus and audio are not in yet.

## Run it

Double-click `index.html`. That is all: it is plain HTML + JavaScript with classic `<script>` tags, no modules, no `fetch`, no server, no Python, no Node, no install. (`index.html#play` skips the title screen.)

## Controls

| Key | Action |
|---|---|
| Arrows / WASD | Move (left/right + limited depth up/down) |
| J or Z | Punch; press again to chain jab, combo, high-kick finisher |
| K or X | Kick (also cancels a jab) |
| L or C | Special long-range kick (knocks down) |
| Space | Jump; J / Z in the air = air kick |
| Shift (hold) | Block (blocks 80% of normal hits, not knockdown specials) |
| P or Esc | Pause |
| R | Restart run |
| Enter | Start / try again |
| F1 or ` | Debug overlay (hurtboxes green, active hitboxes red, pivots yellow, states, FPS) |

Holding an attack key never auto-repeats; every attack needs a fresh key press.

## Folder structure

```
index.html            loads everything with plain <script> tags
css/style.css         integer-scaled, pixelated canvas
src/                  engine (no art or balance numbers in here)
  util.js animation.js input.js font.js fighter.js ai.js stage.js game.js main.js
data/                 everything data-driven
  characters.js       animations (frame lists + tick durations), attacks, hitboxes, AI params
  stages.js           stage list, floor band, enemy waves
  atlas_*.js          GENERATED by tools/extract.html (frame rectangles + foot pivots)
assets/
  reference/          the original concept sheets, untouched
  sprites/            GENERATED transparent atlases (nina.png, goon.png)
  stages/             stages_strips.webp; the game crops and scales each panorama at load time
tools/                only needed when you change the sprites
  extract.html        open in a browser: pick the files from assets/reference/, download new atlases
  extract.js          the extraction pipeline (flood-fill keying, scaling, packing, PNG output)
  manifest.js         hand-measured frame rectangles for every sheet
```

The game itself never needs the tools: the generated atlases are committed. To change sprites, edit `tools/manifest.js`, open `tools/extract.html` in any browser, select the sheets from `assets/reference/`, and save the downloaded `.png` files into `assets/sprites/` and the `atlas_*.js` files into `data/`. (A page opened from disk cannot read the pixels of images it loads by URL, which is why the tool uses a file picker.) Its output was checked against the earlier Python-generated atlases: identical frame tables and identical transparency on every pixel.

## How the pipeline works

1. **Extraction (offline, `tools/extract.html`).** Each frame is cut with a hand-measured rectangle (never equal-width slicing, never including labels / portraits / UI). The background is keyed out by flood-fill plus enclosed-pocket removal (pockets between the legs of wide stances), edge halos are defringed, baked-in ground shadows and stray specks are removed, the frame is scaled to game size (about 90 px tall), alpha is binarised so it stays crisp, and a foot pivot is computed (centre of the lowest pixels, i.e. the planted foot). Frames are packed into one transparent PNG per character plus a JS data file.
2. **Animation (runtime, `animation.js`).** Named animations with explicit frame lists `[frame, ticks, extra]`. `Animator.play(name)` is a no-op when that animation is already playing, so state code can call it every tick without restarts. Playback speed is configurable (`Animator.speed`, per-animation `speed`). Once-animations hold their last frame and set `done`.
3. **Attack timing.** Phases come from the animation data: frames before the first `act` frame are startup, `act` frames are active (the hitbox exists only then), frames after are recovery. A target can be hit once per attack.
4. **Collision.** Sprite rectangles are never used. Each fighter has a hurtbox and each attack a hitbox, both defined relative to the foot pivot, plus a depth-lane check (12 px) so fighters on different lanes do not hit each other.
5. **Timestep.** Fixed 60 Hz simulation with an accumulator; rendering is separate, so speed is identical at 30, 60, 120 or 144 fps.
6. **Resolution.** 480x270 internal canvas, scaled by whole numbers to fit the window.

Adding a fighter = extract an atlas, add one entry to `data/characters.js`. The engine does not change.

## Testing done (Stage 2/3)

Run in the browser pane with scripted input and a paused loop:

- jab timing: startup, 4 active ticks, recovery, return to idle
- holding J for 60 ticks triggers exactly one attack
- J, J, J chains jab, combo, finisher, then returns to idle
- walk animation cycles through its frames (no restart every tick)
- hit lands once, applies damage, hurt state and knockback; a fighter in another depth lane is not hit
- three hits force knockdown; every enemy state sequence ends: hurt, fall, down, getup, idle (118 ticks)
- killing an enemy: dead state, then removed, score awarded
- enemy AI: attacks, never more than two attackers at once, player can die, lives drop, game over appears, Enter restarts
- bot playthrough of the whole stage: 3 waves cleared, camera locks and unlocks, STAGE CLEAR reached, no fighter stuck in any state for over 400 ticks
- jump, air kick, landing; blocking reduces damage from 6 to 2; pause and resume
- no console errors

Manual checklist for you:

1. Frame rate: let the game run at 60 Hz and (if you can) a 120/144 Hz display. Movement and attack speed should look the same.
2. Foot placement: walk Nina up and down the street; her feet should stay on the paving, shadow under her, no sinking or floating between poses.
3. Hold J down: only one punch.
4. Get knocked down: she lies down, gets up, and blinks while invulnerable.
5. Walk to the end of a wave: camera locks, enemies walk in from both sides, "GO >" appears when all are down.
6. F1 overlay: green box roughly fits the body, red box appears only during the active frames.

Opening `index.html` straight from disk (`file://`, no server) was checked in headless Google Chrome: title screen and gameplay scene (stage, sprites, HUD) render with no console errors. Keyboard play was tested through the preview pane over http, not on `file://`.

Not tested: Firefox / Safari, gamepads (not supported), touch.

## Known limitations / missing assets

- **Nina has no knockdown or lying art in the concept sheet.** Falling = hurt pose tilted; lying = block pose rotated 90 degrees. Placeholder until frames are drawn.
- **Goon has no hurt frame** (re-uses guard) and no get-up frames (guard then idle).
- Nina's throw, grab and knife frames are extracted but unused (no grab system yet).
- The concept art is AI-rendered, not true indexed pixel art, so sprites are slightly soft after downscaling and pixel sizes are not perfectly uniform.
- Stage backdrop is one scrolling picture with generated paving: no multi-layer parallax yet, and the panorama is not tileable (the stage ends where the picture ends). Stages 2-6 have no art.
- No audio, no character select, no pause menu beyond the overlay.
- Ray, Mitsuyo, Pimp, Polish Uncle and Bad Girl sheets are in `assets/reference/` but not extracted yet. Mitsuyo's and Ray's grapple poses have an opponent baked into the sprite and need separate attacker/victim art or a different grab presentation.
